Conventions

  • Calls go down. A component may call its own layer or a lower one, never a higher one, and the call graph has no cycles.
  • Events go up. Lower layers reach higher ones only through events or a handler the higher layer registered.
  • Plugins meet core at a contract. Core never imports provider code, and a plugin never touches the databases.
  • Outside text is data. Anything that handles text from outside is marked untrusted, and its text reaches a model only as UntrustedText.
  • Mutations are gated in code. The operation registry's confirm gate, not a prompt, decides whether anything changes: a change is a proposal until a person confirms it.

Call flows

Each step is one call from one component into another, checked against the declared relationships at build time.

An item arrives

#FromToWhat happensNotes
1Providers→Intakesubmit(item) callbackThe provider is handed a callback; it never imports intake.
2Intake→Jobsenqueue the format jobDurable, so a crash loses nothing.
3Jobs→Intakerun the format job callbackA handler intake registered.
4Intake→Formatterssplit into partsDeterministic; no model.
5Intake→Triagersask each triagerAny reject ends it; the last to answer decides.
6Intake→Labelswrite each answering triager's labelsUnder that triager's own name.
7Intake→Jobsenqueue the store jobAccepted items only.
8Jobs→Intakerun the store job callbackA handler intake registered.
9Intake→Items ingestoringestThe one active ingestor.
10Intake→Change logrecord the ingestContent-free.

A scheduled task runs

#FromToWhat happensNotes
1Scheduler→Jobsenqueue the task's jobThe job carries a dedupe key naming the slot.
2Jobs→Plugin hostrun the plugin's job handler callbackRegistered at start as plugin.NAME.KIND.
3Plugin host→Providerscall the handlerFor example an exec instance running a program.
4Providers→Intakesubmit(row) callbackOne item per row it printed.
